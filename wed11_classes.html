Section 2 · 30 minutes

One spark, one object

The class below has the same shape as session 5's Pet: __init__ sets up each new spark's own attributes, and a method, step, changes them, the way feed changed a pet's hunger.

One line in the class below needs explaining first. A spark is launched with a speed and an angle, but the program has to move it in two separate directions each frame: some amount across, and some amount up. Splitting one speed-and-angle into those two amounts is what cos and sin do.

Speed 10 at 60 degrees gives 5.0 across and 8.66 up. You can check those two numbers are right without knowing any trigonometry: 5.0 squared plus 8.66 squared is 100, and the speed squared is also 100. The across-amount and the up-amount always fit the original speed exactly.

math.radians is a unit change, nothing more. Python's cos and sin want radians and you are thinking in degrees, so you convert. Treat all three as tools for today. You do not need to know how they work inside.

Speed 10 at 60 degrees. cos gives the across amount and sin gives the up amount. self.dy is stored as a negative number because moving up the screen makes y smaller.

plume.py

class Particle:
    """One thrown speck that keeps a trail of where it has been."""

    def __init__(self, x, y, speed, angle):
        self.x = x
        self.y = y
        self.dx = speed * math.cos(math.radians(angle))
        self.dy = -speed * math.sin(math.radians(angle))
        self.trail = [(x, y)]
        self.alive = 1

    def step(self):
        """Move one frame forward and record the new position."""
        self.dy = self.dy + GRAVITY
        self.x = self.x + self.dx
        self.y = self.y + self.dy

        self.trail.append((self.x, self.y))

        if self.y > HEIGHT - 40:
            self.alive = 0
Download plume.py
Predict first. Why is there a minus sign on self.dy in __init__ but a plus on GRAVITY in step?

Because the screen's y axis points down. dy is how much y changes each frame, so a positive dy moves the particle down the screen and a negative dy moves it up. An angle of 90 degrees means straight up, which on screen means y decreasing, so the initial dy has to be negative. Gravity pulls down the screen, which is y increasing, so it adds.

This is the coordinate system from the cipher console in session 3, where y counts down from the top, the opposite of the one you use in math class. It causes bugs in every program that draws, so say it out loud each time it comes up.

One particle launched at speed 10 and 80 degrees, with a dot every 10 frames. step adds GRAVITY to dy every frame, so dy goes from -9.85 up through 0 to 9.83. step also appends one position to trail every frame. After 164 frames the trail holds 165 points: the starting position and 164 more.

self is the particular spark this call is about. self.x is that spark's own x, not shared with any other. That one idea replaces all five lists and the comment that was holding them together.

The first three particles in plume.py after two calls to step. Each object holds its own six attributes. Remove one particle from the list and its six values leave together, so nothing can end up under the wrong particle.

What to watch for

The predictable error is forgetting self on an attribute inside a method, which gives NameError rather than anything helpful. Second is writing def step(self) and then calling step(p) instead of p.step(). Both are broken pets in session 5, so ask which broken pet it is before you fix it.
