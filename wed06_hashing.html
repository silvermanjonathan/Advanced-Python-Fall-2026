A homemade seal, and a real one

A seal is a short number computed from a message, so a reader can tell whether the message changed on the way. You will build one, break it in about five minutes, and then meet the function that does not break.

When Wednesday 21 October 2026Time 4:00 to 5:30Length 90 minutes

Section 1 · 10 minutes

Opener

In session 3 you turned letters into numbers with ord. Here is the simplest seal you can build out of that: add up the letter positions and wrap the total at 97.

avalanche.py

def letter_sum_seal(text):
    """Return a seal: add up the letter positions, wrap at 97."""
    running = 0
    for ch in text:
        running = running + ord(ch)
    return running % 97

Send the message and the seal. The reader recomputes the seal and compares. If the two disagree, the message changed. That is the whole idea, and it works.

Now break it. On paper: what is the seal of ab, and what is the seal of ba?

Predict first. Both, before you click.
verified output
seal of 'ab' = 1
seal of 'ba' = 1
same seal, different message: True

Identical. Addition does not care what order it gets its numbers in, so every rearrangement of a message carries the same seal. A seal that cannot tell ab from ba cannot tell attack at dawn from any anagram of it, so an attacker can shuffle your message and leave the seal untouched.

Two different messages with the same seal is called a collision. Real hash functions are built specifically to make collisions hard to find.

Section 2 · 25 minutes

sha256

avalanche.py

import hashlib


def sha(text):
    """Return the sha256 hex digest of text."""
    return hashlib.sha256(text.encode()).hexdigest()

Section 3 · 30 minutes

Measure the avalanche

Do not take my word for all of it. Count. A sha256 digest is 256 bits, so convert both digests to bits and count how many positions differ.

def bits_of(hexdigest):
    """Return hexdigest as a string of 0s and 1s."""
    number = int(hexdigest, 16)
    return format(number, "0256b")


def bits_differing(a, b):
    """Return how many bit positions differ between two hex digests."""
    left = bits_of(a)
    right = bits_of(b)

    count = 0
    for i in range(256):
        if left[i] != right[i]:
            count = count + 1
    return count
Predict first. Out of 256 bits, how many do you predict differ? Write a number, not a word.
verified output
dawn vs dusk: 130 of 256 bits differ
dawn vs dawn+period: 124 of 256 bits differ

Around 128 both times, which is half. That is the design goal: each output bit should flip with probability about one half whenever the input changes at all, no matter how small the change. 130 and 124 are what half of 256 looks like when you only sample twice.

Think about what that rules out. You cannot steer the output by nudging the input, because a tiny nudge scatters everything. And you cannot work backwards from a digest, because it holds no trace of which input produced it.

One honest limit. A hash proves a file was not changed. It does not hide anything and it does not prove who sent it. If someone can replace both the file and its posted hash, you learn nothing.

Exits

FLOOR

You built the seal, found a collision in it by hand, and can explain why addition causes it.

MIDDLE

Floor, plus sha256 running on your own strings, plus you can state the avalanche property in your own words.

STRETCH

Middle, plus count the differing bits yourself and run it on five pairs of near-identical strings. Record the five counts and their average. Then try to find any sha256 collision by hand and write down why you stopped.

What to watch for

Do not skip building the seal. A collision found in something you wrote ten minutes ago lands differently from a collision in something handed to you.

Students conclude a hash is encryption. It is not, and the difference is worth ten minutes: encryption is meant to be reversed by the right person, and a hash is meant to be reversed by nobody. Ask them how they would decrypt a digest back to the message and let them work out that the digest is the same length whatever goes in, so most of the message cannot be in there.

The bit-counting loop is the part most likely to defeat the floor group. Have the digest comparison ready as a fallback: line the two hex strings up on the projector and count matching characters instead.
