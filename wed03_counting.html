03

Counting, and what counting buys you

Wednesday 30 September 2026

A dictionary maps each letter straight to its count, which saves you keeping two lists in step by hand. Then you will build a Caesar cipher from nothing, and break one by counting letters instead of guessing keys.

1Opener10 minutes

Last week a module handed values back. On paper: write a function count_of(values, wanted) that returns how many times wanted appears in values. Four lines plus the def.

Predict first. Write yours first.
def count_of(values, wanted):
    """Return how many times wanted appears in values."""
    hits = 0
    for v in values:
        if v == wanted:
            hits = hits + 1
    return hits

Now imagine calling that 26 times, once per letter. It works, and it reads the whole text 26 times. Hold that thought.

2The parallel list problem15 minutes

Here is the version without a dictionary. Two lists, kept in step by hand.

letters = ["a", "b", "c"]
counts = [0, 0, 0]

# to count a letter you first have to find where it lives
for i in range(3):
    if letters[i] == "b":
        counts[i] = counts[i] + 1

A dictionary removes the search. The letter is the key. The count is the value. No index, no second list, no keeping anything in step.

counts = {}
counts["b"] = 0
counts["b"] = counts["b"] + 1
print(counts)
Predict first. What prints? And what happens if you run counts["z"] + 1 without setting counts["z"] first?
verified output
{'b': 1}

The second one raises KeyError: 'z'. A dictionary does not invent a zero for you. That is the whole reason collections.Counter exists.

3What a Caesar cipher is20 minutes

Nothing in this course has needed a cipher yet, so here is the whole idea in one sentence. Pick a number, move every letter forward in the alphabet by that number, and wrap around from z back to a.

Three words come with it and get used for the next four sessions. The number is the key. The readable message is the plaintext. The scrambled message is the ciphertext.

Do one by hand before any code. Key 3, plaintext dawn. Write the alphabet along the top of your page if it helps.

Predict first. Encode dawn with key 3. Then encode zebra with the same key. The second one is the interesting one.

dawn becomes gdzq. d goes to g, a goes to d, w goes to z, n goes to q.

zebra becomes cheud. The z is the interesting part: three past z runs off the end of the alphabet and comes back round to c. Without that wrap the cipher would break on a quarter of the alphabet.

To decode, move backwards by the same key. A Caesar cipher undoes itself with a negative key, which is why one function can do both jobs.

Letters into numbers

Python will not add 3 to a letter. Two functions get you across. ord turns a character into the number the machine stores it as, and chr turns a number back into a character.

print(ord("a"))   # 97
print(ord("d"))   # 100
print(ord("z"))   # 122
print(chr(103))   # g

The numbers themselves do not matter. What matters is that they run in order, so ord(ch) - ord("a") gives you a position from 0 to 25. Add the key to the position, wrap it with % 26, then add ord("a") back on to return to a letter.

Predict first. Walk z with key 3 through all four steps and write the number at each one.
ord("z")            122
122 - ord("a")       25     the position of z
(25 + 3) % 26         2     wraps past the end
chr(2 + ord("a"))   'c'    back to a letter

This is the % wrap from session 1 doing real work. There it kept a number under 9. Here it keeps a letter inside the alphabet.

4Now break one30 minutes

Here is a message somebody encoded with a key you do not have. You could try all 26 keys, and for a Caesar cipher that is genuinely fast enough. Do something better instead: count the letters.

In ordinary English, e is the most common letter. If the most common letter in the ciphertext is h, then e was probably shifted to h, and the key is 3. One count, no guessing.

caesar_crack.py

"""Break a Caesar cipher by letter frequency instead of by guessing."""

from collections import Counter

ciphertext = "uhdg wkh frgh dqg wudfh wkh frgh ehiruh brx hyhu uxq wkh frgh"


def shift_by(text, amount):
    """Return text with every letter rotated forward by amount."""
    out = ""
    for ch in text:
        if ch == " ":
            out = out + " "
        else:
            spot = ord(ch) - ord("a")
            spot = (spot + amount) % 26
            out = out + chr(spot + ord("a"))
    return out


def letter_counts(text):
    """Return a Counter of the letters in text, ignoring spaces."""
    letters = ""
    for ch in text:
        if ch != " ":
            letters = letters + ch
    return Counter(letters)


def guess_shift(text):
    """Return the shift that maps the most common letter onto 'e'."""
    counts = letter_counts(text)
    top_letter = counts.most_common(1)[0][0]
    return (ord(top_letter) - ord("e")) % 26


counts = letter_counts(ciphertext)
print("five most common:", counts.most_common(5))
print("distinct letters used:", len(set(ciphertext.replace(" ", ""))))

k = guess_shift(ciphertext)
print(f"guessed shift {k}")
print("plaintext:", shift_by(ciphertext, -k))
Predict first. Two predictions. What is the most common letter in that ciphertext, and what shift will the program guess?
verified output
five most common: [('h', 12), ('u', 5), ('g', 5), ('r', 5), ('w', 4)]
distinct letters used: 14
guessed shift 3
plaintext: read the code and trace the code before you ever run the code

h appears 12 times, well clear of the 5 behind it. So the key is 3 and the message comes out on the first try, with no key and no guessing.

Two words of caution, and they matter more than the trick. The text has to be long enough for e to actually win, and the text has to be ordinary English. Try it on a short message and watch it fail.

Frequency counts are ratios. 12 of 49 letters is about 0.24. In ordinary English e runs near 0.12. Your sample is small, so your share is off. This is the same reasoning you use on any small sample, and it comes back hard in session 9.

Sets, in one line

set(text) throws away duplicates and order, and keeps only which things appeared. That is what distinct letters used: 14 came from. A set answers which, a Counter answers how many.

FLOOR

You encoded dawn and zebra by hand with key 3, you can say what plaintext, ciphertext, and key mean, and you ran letter_counts on the ciphertext and read the top letter off the output.

MIDDLE

Floor, plus shift_by written and encoding correctly including the wrap past z, plus the full crack running.

STRETCH

Middle, plus break it on purpose: find a message short enough that the most common letter is not e, then write a guess_shift that scores all 26 shifts against English letter frequencies and picks the best total instead of trusting one letter.

Timing

10 opener, 15 parallel lists and Counter, 20 building the cipher, 30 the crack, 15 sets and exits. Assume no student has seen a cipher before. Do not cut section 3 to save the crack: a crack on something they did not build is a magic trick, not a lesson. Cut the sets section if pressed.

What to watch for

The hand encode is the part to insist on. Students who go straight to ord without doing dawn on paper will not spot the wrap, and the wrap is the only hard part of the cipher.

Expect ord and chr to feel arbitrary. The fix is to say the actual numbers do not matter, only that they run in order. Nobody needs to memorise 97.

KeyError is the new traceback this week and students read it as a crash rather than as information. Say the sentence out loud: a dictionary does not invent a zero for you.

Some students will want to brute force all 26 shifts because it is easier to write. Let them, then ask what they would do with a Vigenere key of length 7. Brute force stops being available and counting does not.
