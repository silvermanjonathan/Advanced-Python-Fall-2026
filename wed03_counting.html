Counting, and what counting buys you

Wednesday 30 September 2026

Counting things with two lists kept in step is work you do not have to do. A dictionary maps each letter straight to its count, and once you can count letters you can break a Caesar cipher without trying all 26 keys.

1Opener10 minutes

Last week a module handed values back. On paper: write a function count_of(values, wanted) that returns how many times wanted appears in values. Four lines plus the def.

Predict first. Write yours first.
def count_of(values, wanted):
    """Return how many times wanted appears in values."""
    hits = 0
    for v in values:
        if v == wanted:
            hits = hits + 1
    return hits

Now imagine calling that 26 times, once per letter. It works, and it reads the whole text 26 times. Hold that thought.

2The parallel list problem15 minutes

Here is the version without a dictionary. Two lists, kept in step by hand.

letters = ["a", "b", "c"]
counts = [0, 0, 0]

# to count a letter you first have to find where it lives
for i in range(3):
    if letters[i] == "b":
        counts[i] = counts[i] + 1

A dictionary removes the search. The letter is the key. The count is the value. No index, no second list, no keeping anything in step.

counts = {}
counts["b"] = 0
counts["b"] = counts["b"] + 1
print(counts)
Predict first. What prints? And what happens if you run counts["z"] + 1 without setting counts["z"] first?
verified output
{'b': 1}

The second one raises KeyError: 'z'. A dictionary does not invent a zero for you. That is the whole reason collections.Counter exists.

3Counter, then the crack40 minutes

Here is the program. The ciphertext is a real Caesar shift of an English sentence. The program never tries 26 keys. It counts letters, finds the most common one, and assumes it is e.

caesar_crack.py

"""Break a Caesar cipher by letter frequency instead of by guessing."""

from collections import Counter

ciphertext = "uhdg wkh frgh dqg wudfh wkh frgh ehiruh brx hyhu uxq wkh frgh"


def shift_by(text, amount):
    """Return text with every letter rotated forward by amount."""
    out = ""
    for ch in text:
        if ch == " ":
            out = out + " "
        else:
            spot = ord(ch) - ord("a")
            spot = (spot + amount) % 26
            out = out + chr(spot + ord("a"))
    return out


def letter_counts(text):
    """Return a Counter of the letters in text, ignoring spaces."""
    letters = ""
    for ch in text:
        if ch != " ":
            letters = letters + ch
    return Counter(letters)


def guess_shift(text):
    """Return the shift that maps the most common letter onto 'e'."""
    counts = letter_counts(text)
    top_letter = counts.most_common(1)[0][0]
    return (ord(top_letter) - ord("e")) % 26


counts = letter_counts(ciphertext)
print("five most common:", counts.most_common(5))
print("distinct letters used:", len(set(ciphertext.replace(" ", ""))))

k = guess_shift(ciphertext)
print(f"guessed shift {k}")
print("plaintext:", shift_by(ciphertext, -k))
Predict first. Two predictions. What is the most common letter in that ciphertext, and what shift will the program guess?
verified output
five most common: [('h', 12), ('u', 5), ('g', 5), ('r', 5), ('w', 4)]
distinct letters used: 14
guessed shift 3
plaintext: read the code and trace the code before you ever run the code

h appears 12 times. h is three letters past e, so the shift is 3, and the message comes out first try. Notice the % 26: it is the same wrap you traced by hand in session 1, on a clock with 26 hours instead of 9.

Two words of caution, and they matter more than the trick. The text has to be long enough for e to actually win, and the text has to be ordinary English. Try it on a short message and watch it fail.

Frequency counts are ratios. 12 of 49 letters is about 0.24. In ordinary English e runs near 0.12. Your sample is small, so your share is off. This is the same reasoning you use on any small sample, and it comes back hard in session 9.

Sets, in one line

set(text) throws away duplicates and order, and keeps only which things appeared. That is what distinct letters used: 14 came from. A set answers which, a Counter answers how many.

FLOOR

You can explain why a dictionary beats two parallel lists, and you ran letter_counts on the ciphertext and read the top letter off the output.

MIDDLE

Floor, plus the full crack running, plus you can say why the program divides nothing and still finds a ratio.

STRETCH

Middle, plus break it on purpose: find a message short enough that the most common letter is not e, then write a guess_shift that scores all 26 shifts against English letter frequencies and picks the best total instead of trusting one letter.

What to watch for

KeyError is the new traceback this week and students read it as a crash rather than as information. Say the sentence out loud: a dictionary does not invent a zero for you.

Some students will want to brute force all 26 shifts because it is easier to write. Let them, then ask what they would do with a Vigenere key of length 7. Brute force stops being available and counting does not.
