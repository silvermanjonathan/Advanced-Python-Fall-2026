Before the loop

  • pygame.init() starts pygame. It comes before anything else from pygame.
  • pygame.display.set_mode((640, 400)) opens a window 640 pixels wide and 400 pixels tall. A pixel is one dot of the screen. The window is stored in screen, and everything you draw goes onto screen.
  • clock = pygame.time.Clock() makes a clock. The loop uses it to control its speed.
  • running controls the loop. while running: keeps going while running is 1 and stops when it is 0. It starts at 1.

(640, 400) is a tuple: values in round brackets, separated by commas, kept together as one value. That is why the line has two pairs of brackets. The outer pair are the brackets of the call to set_mode, the same as in print(...). The inner pair make the tuple. pygame uses tuples for sizes, colors, and rectangles.

BOARD = (15, 19, 24) is a color. A color is a tuple of three numbers: how much red, how much green, and how much blue, each from 0 to 255. (0, 0, 0) is black and (255, 255, 255) is white. (15, 19, 24) has a little of each, so it is nearly black.

The loop

Each pass through the while loop draws one picture. One picture is called a frame. Each pass does three things, in this order:

  1. Read the events. An event is something that happened since the last frame, such as a key press or a click. pygame.event.get() gives a list of them, and the for loop looks at each one. pygame.QUIT is the event for the window's close button.
  2. Draw. screen.fill(BOARD) paints the whole window one color. Drawing happens out of sight.
  3. Show. pygame.display.flip() puts the finished drawing on the screen. clock.tick(60) waits long enough that the loop runs no more than 60 times a second.

After the loop, pygame.quit() closes the window.

Predict first. You click the window's close button. Which lines run, in order, from that click until pygame.quit()?
  1. pygame.event.get() gives an event whose type is pygame.QUIT.
  2. The gate if event.type == pygame.QUIT: says yes, so running = 0 runs.
  3. The rest of that pass still runs: screen.fill(BOARD), pygame.display.flip(), clock.tick(60).
  4. Back at while running:, running is 0, so the loop stops.
  5. pygame.quit() runs and the window closes.

Nothing else in the program sets running to 0. The window never closes itself. You close it.

Predict first. At 60 frames a second, how many frames does the loop draw in 2 seconds?

60 × 2 = 120 frames.

Section 3 · 10 minutes

Rectangles

Every point in the window has two numbers, x and y. x counts pixels across from the left edge. y counts pixels down from the top edge. The top left corner is (0, 0). In math class y goes up. In pygame y goes down.

pygame.draw.rect(screen, TILE, (x, 130, 20, 26)) draws a filled rectangle on screen in the color TILE. The tuple is (x, y, width, height). The top left corner of the rectangle is at (x, 130), and the rectangle is 20 pixels wide and 26 pixels tall.

console_2_tiles.py

"""Cipher console, step 2: a row of 26 tiles, one for each letter."""

import pygame

BOARD = (15, 19, 24)
TILE = (242, 233, 211)

pygame.init()
screen = pygame.display.set_mode((640, 400))
clock = pygame.time.Clock()
print(f"first tile starts at x = {20 + 0 * 23}")
print(f"last tile starts at x = {20 + 25 * 23}")

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    screen.fill(BOARD)

    for i in range(26):
        x = 20 + i * 23
        pygame.draw.rect(screen, TILE, (x, 130, 20, 26))

    pygame.display.flip()
    clock.tick(60)

pygame.quit()

Inside the while loop, the for loop draws 26 tiles, one for each letter. Tile i starts at x = 20 + i * 23: 20 pixels in from the left edge, then 23 more for each tile before it. A tile is 20 pixels wide, so there is a gap of 3 pixels between tiles.

Predict first. Where does the first tile start? Where does the last tile start? Does the last tile fit inside the 640 pixel window?

The first tile is i = 0: 20 + 0 × 23 = 20.

The last tile is i = 25: 20 + 25 × 23 = 595.

The last tile is 20 pixels wide, so its right edge is at 595 + 20 = 615. That is inside 640, so it fits.

Section 4 · 10 minutes

Letters

This course does not use pygame to write words, so each letter is drawn from small squares. letters.py holds a dictionary called SHAPES with one entry for each letter and one for the space. Here is the entry for a:

letters.py, one entry of SHAPES

"a": [".#.", "#.#", "###", "#.#", "#.#"],

Each string is one row, top to bottom. # is a filled square and . is an empty one.

You do not need to read the rest of letters.py. You need its two functions. import letters works the same way import sweep_tools did in session 2.

  • letters.draw_letter(screen, letter, x, y, size, color) draws one letter with its top left corner at (x, y). size is how many pixels wide each square is, so a letter is 3 × size wide and 5 × size tall.
  • letters.draw_word(screen, word, x, y, size, color) draws a whole word, with one square of space between letters.

console_3_board.py

"""Cipher console, step 3: the alphabet, the coded alphabet, and the message."""

import pygame

import letters

MESSAGE = "attack at dawn"
KEY = 3
ALPHABET = "abcdefghijklmnopqrstuvwxyz"

BOARD = (15, 19, 24)
TILE = (242, 233, 211)
TILE_INK = (27, 31, 38)
CODED_TILE = (31, 46, 39)
CODED_INK = (123, 228, 149)
PLAIN_INK = (150, 143, 128)


def shift_by(text, amount):
    """Return text with every letter rotated forward by amount."""
    out = ""
    for ch in text:
        if ch == " ":
            out = out + " "
        else:
            spot = ord(ch) - ord("a")
            spot = (spot + amount) % 26
            out = out + chr(spot + ord("a"))
    return out


coded = shift_by(MESSAGE, KEY)
coded_row = shift_by(ALPHABET, KEY)
print(f"plain: {MESSAGE}")
print(f"coded: {coded}")
print(f"coded row: {coded_row}")

pygame.init()
screen = pygame.display.set_mode((640, 400))
clock = pygame.time.Clock()

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0

    screen.fill(BOARD)

    for i in range(26):
        x = 20 + i * 23
        pygame.draw.rect(screen, TILE, (x, 130, 20, 26))
        letters.draw_letter(screen, ALPHABET[i], x + 7, 138, 2, TILE_INK)
        pygame.draw.rect(screen, CODED_TILE, (x, 190, 20, 26))
        letters.draw_letter(screen, coded_row[i], x + 7, 198, 2, CODED_INK)

    letters.draw_word(screen, MESSAGE, 40, 50, 4, PLAIN_INK)
    letters.draw_word(screen, coded, 40, 280, 4, CODED_INK)

    pygame.display.flip()
    clock.tick(60)

pygame.quit()

shift_by is the function you wrote in section 3 of session 3, copied in unchanged.

coded_row = shift_by(ALPHABET, KEY) codes the whole alphabet in one call.

In the tile loop, ALPHABET[i] is the letter at index i of the string ALPHABET. A string has indexes the same way a list does, so ALPHABET[0] is a. coded_row[i] is what that letter becomes, so the loop draws it on the tile directly under it.

x + 7 and 138 put each letter in the middle of its tile. At size 2 a letter is 6 pixels wide and 10 tall. The tile is 20 wide, which leaves 7 pixels on each side, and 26 tall, which leaves 8 above and 8 below: 130 + 8 = 138.

Predict first. With KEY = 3, which letter is on the tile under x? Which letter is on the tile under z?

Under x: x is at position 23, counting a as 0. 23 + 3 = 26, and 26 % 26 = 0, so the letter is a.

Under z: z is at position 25. 25 + 3 = 28, and 28 % 26 = 2, so the letter is c.

coded: dwwdfn dw gdzq
coded row: defghijklmnopqrstuvwxyzabc

Change KEY to 10 and run it again. The bottom row now starts with k and ends with j.

MESSAGE rules. Keep MESSAGE to 37 characters or fewer, or the end runs off the right edge. Use lowercase letters and spaces only. SHAPES has no entry for a capital letter or a period, so MESSAGE = "Attack at dawn" stops with the same error a plain dictionary gave you in session 3 for a missing key:

Section 5 · 10 minutes

Make it move

cipher_console.py starts from console_3_board.py. It adds one color, GLOW, for the boxes, and changes the program in three places. Here they are, one at a time.

Two accumulators

Before the loop:

cipher_console.py

frame = 0
shown = 0

frame counts the frames drawn so far. shown counts how many coded letters are showing. Both start at 0, like the accumulators in the session 3 opener.

At the end of the loop body, just before flip:

cipher_console.py

    frame = frame + 1
    if frame % 30 == 0 and shown < len(MESSAGE):
        shown = shown + 1

Every frame adds 1 to frame. frame % 30 is 0 on frames 30, 60, 90, and so on, so on every 30th frame one more coded letter shows. At 60 frames a second, that is one letter every half second. shown < len(MESSAGE) stops shown once every letter is showing.

Draw the letters that are showing

cipher_console.py

    for i in range(shown):
        letters.draw_letter(screen, coded[i], 40 + i * 16, 280, 4, CODED_INK)

These two lines take the place of the line that drew all of coded in step 3. They draw the first shown letters of coded. A letter at size 4 is 12 pixels wide, and the letters are 16 pixels apart, so there are 4 pixels between them.

Box the letter being coded

cipher_console.py

    if shown < len(MESSAGE) and MESSAGE[shown] != " ":
        spot = ord(MESSAGE[shown]) - ord("a")
        x = 20 + spot * 23
        pygame.draw.rect(screen, GLOW, (x - 3, 127, 26, 32), 3)
        pygame.draw.rect(screen, GLOW, (x - 3, 187, 26, 32), 3)

MESSAGE[shown] is the next letter to be coded. spot is its position in the alphabet, worked out the same way as in shift_by. The two rectangles go around its tile and around the tile under it.

Each box is 3 pixels bigger than its tile on every side. The top tile starts at (x, 130) and is 20 by 26, so the box starts at (x - 3, 127) and is 26 by 32. The last number, 3, tells pygame to draw the outline only, 3 pixels thick, instead of a filled rectangle.

A space has no tile, so the gate skips spaces.

When shown reaches the end of the message, shown < len(MESSAGE) is False, and Python does not check the right side of and at all. That matters, because there is no letter at that index. With the two sides swapped, the program stops as soon as the last coded letter shows:

verified output, verify_console.py
IndexError: string index out of range
Predict first. "attack at dawn" has 14 characters, counting the two spaces. How many seconds until the whole coded message is showing?

One letter every 30 frames, so 14 × 30 = 420 frames. At 60 frames a second, 420 ÷ 60 = 7 seconds.

Running the program for exactly 419 frames, and then for exactly 420, shows shown reaching 14 on frame 420:

after 420 frames, shown is 14

Predict first. Make the R key start the coded message again from nothing.

A key press is an event, like the close button. It arrives in the same for event loop.

event.type == pygame.KEYDOWN is True when the event is a key being pressed. event.key == pygame.K_r is True when that key is R. You need both, so join them with and, with the event.type check first.

Starting again means putting the two accumulators back to their starting values.

cipher_console_replay.py

    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
        if event.type == pygame.KEYDOWN and event.key == pygame.K_r:
            frame = 0
            shown = 0

After R, frame counts up from 0 again. 100 frames later it has passed 30, 60, and 90, so shown is 3:

verified output, verify_console.py
R pressed on frame 600, shown is 3 after frame 700

The order of the two checks matters, for the same reason as the box gate in section 5. Only a key event has event.key. Moving the mouse makes an event too, and with the two sides swapped, the first mouse movement stops the program:

verified output, verify_console.py
AttributeError: 'pygame.event.Event' object has no attribute 'key'

With event.type == pygame.KEYDOWN first, a mouse event makes the left side False, and Python never reads event.key.
