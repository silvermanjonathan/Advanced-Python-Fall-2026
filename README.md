## Prerequisites

Stated in full on the hub. Variables and reassignment; `print` and f-strings; `if` /
`elif` / `else` and comparisons; `for i in range(n)` with a counter or running total; a
list and `values[i]`; `def` with parameters, even if their functions have only ever
printed.

Everything else is treated as new, including `return` values, dictionaries, files, and
classes.

**No mathematics beyond grade 5 arithmetic is assumed.** Four things the course needs are
introduced from zero where they are first used, and the hub says so in a table:

| Introduced in | What, and how far it goes |
|---|---|
| Session 3 | Cryptography from nothing: what a Caesar cipher does, and the words plaintext, ciphertext, key. Students encode `dawn` and `zebra` by hand, including the wrap past z, before touching `ord` or `chr`. |
| Session 10 | Logarithms, only as far as "what power of ten gives this number". The calculator does the arithmetic. |
| Session 12 | Splitting a speed and an angle into an across amount and an up amount. Given as a tool, with a squares check students can verify themselves (5.0 and 8.66 against a speed of 10). |
| Session 13 | The Pythagorean theorem, stated plainly as the distance rule, with a worked non-collapsing case. |

Session 1 is deliberately a diagnostic. Advanced enrollment at an after-school program is
usually parent-chosen rather than skill-verified, and the band here is grades 5 to 8, so
session 1 uses only the prerequisite list and measures tracing. If a third of the room
cannot trace an accumulator, slow sessions 2 and 3.

## Verification

Every output printed on a page came from running the program, on Python 3.12.3 with
pygame 2.6.1. The two graphics sessions were verified headless.

```
cd build
python3 make.py        # writes all 16 pages, then validates
python3 crosscheck.py  # runs every program, asserts each quoted line appears
```

`make.py` checks tag balance, reveal and answer parity, escaped angle brackets in `<pre>`
blocks, link resolution, dash characters and entities, and absence of browser storage.
`crosscheck.py` runs each program and asserts that every line quoted on its page appears
in the real stdout, including the broken Monty Hall variant and the session 13 table of
other starting speeds, which `verify_orbit_band.py` produces by running `orbit.py` with
the frame clock switched off.

Also verified in a headless browser before the first printing: no horizontal overflow on
any of the 14 pages at 390px, and all 41 reveal buttons toggle. The second printing added
three reveals (44 now) without changing the button markup or the script beyond an
`aria-controls` attribute, and was not re-run in a browser.

**Session 7's timings are machine specific** and will not match the classroom machines.
The shape holds, which is what the session is about. Re-run before teaching it.

## Self-containment

Every backward reference in the course points at a session in the course, verified by an
audit that parses each page for "session N" and checks that N precedes it. The only
forward references are the pager links and three deliberate signposts: the capstone
deadline in sessions 9 and 10, and the seed discussion in session 8.

**Page rule, added in the second printing:** anything an exit assesses must appear on the
student side of the page, not only in the teacher panel and not only in the file on the
machines. Three faults in the first printing (session 4's report writing, session 7's two
searches, session 1's slow path) lived in a panel or nowhere. Session 5 now shows
`to_grid` and says that `rail_decode` is the student's to write.

Session 10 is the first window in the course, so `benford_histogram.py` is shown in full
there, with the frame-loop idiom read before the drawing, and the terminal-and-window rule is
stated there rather than assumed. Sessions 1, 6, and 12 build their own starting material rather
than recalling any: `gate_log.py` gives session 1 a second style-pass target,
`sparks_parallel.py` gives session 12 a live parallel-list failure to react to, and
session 6 builds the letter-sum seal in its first ten minutes before breaking it.

Session 3 teaches the Caesar cipher before cracking one. That ordering is deliberate and
should not be reversed for time: a crack on a mechanism the student did not build is a
magic trick rather than a lesson, and the teacher panel says so.

An audit lists every second-person claim on every page ("you traced", "you built",
"you found") and each one now resolves either to work done inside that same session or to
a named earlier session. The phrase "all term" survives in three places, and in all three
it is a forward-looking rule for the term ahead rather than a claim about past work.

## Standards

Mapped to the Common Core State Standards for Mathematics (Multi-State). All 27 codes and
their wording were retrieved from the CASE Network through the Learning Commons Knowledge
Graph on 12 September 2026. At most three per session. Footers say "mapped to".

Two deliberate deviations from the retrieved text, both declared on every page that shows
a standards list. The "for example" illustrations attached to `7.SP.C.6` and `8.EE.A.1`
are omitted, because they illustrate rather than state the standard. And mathematical
markup in the source is rendered as plain text, so `7.SP.C.5`'s fraction appears as 1/2.
Nothing else is shortened.

`6.SP.B.5.a` and `6.SP.B.5.c` are the lettered children of `6.SP.B.5`. The parent's own
statement is only a stem ending in a colon, so it is unusable in a teacher panel; the
children carry the stem and are quoted in full. `make.py` now rejects any page whose
standards list contains a statement ending in a colon, a semicolon, or "such as by".

The graph carries Common Core and state-adopted frameworks. It returned nothing for New
York's Computer Science and Digital Fluency codes in any format tried, and it rejects CSTA
as a jurisdiction outright, naming `Multi-State` or a US state as the only options. So
**no CSTA or New York code appears anywhere on this site**, because none could be
verified. Paste the codes you want and they can be added under the usual `??` flags.

Three codes fit the material almost exactly. `8.F.A.1` defines a function as a rule
assigning each input exactly one output, which is session 2. `7.SP.C.6` is long-run
relative frequency, which is session 9. `7.SP.C.7` asks students to explain sources of
discrepancy when a model and observed frequencies disagree, which session 9 does with a
real bug supplying the discrepancy.

## Code rules

Version 1, dated 12 September 2026. Published in full on the hub. Summary:

One frame-loop idiom: `while running:`, an `event.get()` loop, a QUIT listener,
`clock.tick(60)`. A window never closes itself. Flat gates only. Words in the terminal,
visuals in the window. No `pygame.font`. No bare `except:`. A module never prints. No
turtle, since it does not work in our VS Code setup.

`break` is lifted from session 7 and only where the loop exit is itself the topic. Before
that, every `while` names its exit condition.
