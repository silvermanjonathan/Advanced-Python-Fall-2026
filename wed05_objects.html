Making your own objects

Strings, lists, and dictionaries are objects that someone else designed. Today you write a class, the code that describes a new kind of object, and make virtual pets from it. Each pet keeps its own hunger and its own happiness.

Section 1 · 10 minutes

Opener: objects you already use

Every value in Python is an object, and every object is made from a class. The class says what its objects store and what they can do.

This program uses a string and two lists, which you have used since session 1, and a dictionary like the one in session 3. It also uses one new function, type, which tells you the class of a value.

objects_tour.py

"""Session 5 opener: values you have already used are objects."""

word = "dawn"
row = ["#", ".", "#"]
other = ["x"]
code_names = {"a": "otter"}

print(type(word))
print(type(row))
print(type(code_names))

row.append("#")
print(row)
print(other)

verified output
<class 'str'>
<class 'list'>
<class 'dict'>
['#', '.', '#', '#']
['x']

str, list, and dict are classes. "dawn" is one object made from the str class, and row is one object made from the list class.

row.append("#") changed row and nothing else. The dot means this object's: row.append is row's own append, so it adds to row's items and leaves other alone. Each list keeps its own items.

The session 3 console did the same thing. clock = pygame.time.Clock() made one object from the Clock class, and clock.tick(60) called that clock's own tick. In session 4, event.key read a value stored on one event object: which key was pressed. Today you write a class of your own.

Section 2 · 30 minutes

Build a pet, one piece at a time

Do this now. Make a new file called pets.py. Type each piece as you reach it and run the file after each one. Answer each question before you open its answer.

Piece 1: an empty class

class Pet:
    pass

class Pet: starts a class called Pet. Class names start with a capital letter, so you can tell a class from a variable. pass means nothing here yet. Python needs at least one line inside a class, and pass is a line that does nothing.

Predict first. You run this file. What appears in the terminal?

Nothing. The file describes what a pet is, but no line makes a pet, and no line prints. Writing a class does not make an object.

Piece 2: setting up a new pet

class Pet:
    def __init__(self, name):
        self.name = name


rocky = Pet("Rocky")
print(rocky.name)
Predict first. What does it print? Then say what the difference is between Pet and rocky.
verified output
Rocky

Pet is the class. rocky is one pet made from it. A thing made from a class is called an object or an instance of that class. The two words mean the same thing.

Pet("Rocky"), with brackets, makes a new pet. Python makes an empty object, then straight away runs __init__ on it, with self set to the new object and name set to "Rocky". __init__ is short for initialise, which means set up. It has two underscores on each side.

self.name = name stores the name on this pet. name is a parameter, and like every parameter it is gone when __init__ finishes. self.name belongs to the pet and stays. rocky.name reads it back: rocky's name.

Piece 3: numbers every pet starts with

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 5
        self.happiness = 5


rocky = Pet("Rocky")
print(rocky.name, rocky.hunger, rocky.happiness)
Predict first. Pet("Rocky") only passes a name. What does it print, and where do the other two numbers come from?
verified output
Rocky 5 5

Every new pet starts with hunger 5 and happiness 5, because __init__ sets them to 5 for every pet it sets up. A value stored on an object like this is called an attribute. A pet has three: name, hunger, and happiness. Only the name comes from the line that makes the pet. To let pets start with different hunger, you would add a hunger parameter to __init__ and pass a number in.

Piece 4: things a pet can do

A function written inside a class is called a method. Add these two below __init__, indented 4 spaces, the same as __init__, so they are inside the class.

    def feed(self):
        """Make this pet 1 less hungry."""
        self.hunger = self.hunger - 1

    def play(self):
        """Make this pet 1 happier."""
        self.happiness = self.happiness + 1
Predict first. self appears in two kinds of places in feed. Find both and say what each one does. Then: rocky.feed() has nothing in its brackets, but feed has one parameter. Where does the value of that parameter come from?

The first place is def feed(self):, the parameter list. The first parameter of every method is self. It holds the pet the method is working on.

The second place is self.hunger = self.hunger - 1, in the body. self.hunger means this pet's hunger. The line reads this pet's hunger, takes 1 off, and stores the answer back on the same pet.

The value comes from the dot. When you write rocky.feed(), Python runs feed with self set to rocky. The object before the dot becomes self. luna.feed() runs the same lines with self set to luna.

Piece 5: a method that returns

Session 2's rule holds inside a class too: a function that works out a value returns it, and the caller prints it. report builds one line about the pet and returns it. Add it below play.

    def report(self):
        """Return one line about this pet."""
        return f"{self.name}: hunger {self.hunger}, happiness {self.happiness}"

Then, below the class, make a pet and call report two ways:

rocky = Pet("Rocky")
rocky.report()
print(rocky.report())
Predict first. Two calls to report, one inside print and one not. What appears in the terminal?
verified output
Rocky: hunger 5, happiness 5

One line, not two. rocky.report() on a line by itself returns the line and nothing prints it, so it is thrown away. print(rocky.report()) prints whatever report returned. This is session 2's print is not return, inside a class.

Piece 6: two pets at once

Here is the whole of pets.py. The part at the bottom makes two pets and treats them differently. The last line asks for the class of rocky, the way the opener asked for the class of a string.

pets.py

"""Session 5: a class for a virtual pet, and two pets made from it."""


class Pet:
    """A virtual pet that keeps its own name, hunger, and happiness."""

    def __init__(self, name):
        self.name = name
        self.hunger = 5
        self.happiness = 5

    def feed(self):
        """Make this pet 1 less hungry."""
        self.hunger = self.hunger - 1

    def play(self):
        """Make this pet 1 happier."""
        self.happiness = self.happiness + 1

    def report(self):
        """Return one line about this pet."""
        return f"{self.name}: hunger {self.hunger}, happiness {self.happiness}"


# make two pets from the one class
rocky = Pet("Rocky")
luna = Pet("Luna")

rocky.feed()
rocky.feed()
luna.play()

print(rocky.report())
print(luna.report())
print(type(rocky))
Download pets.py
Predict first. Write all three lines on paper before you open the answer. Then say why Luna's hunger is not 3.
verified output
Rocky: hunger 3, happiness 5
Luna: hunger 5, happiness 6
<class '__main__.Pet'>

Rocky was fed twice, so Rocky's hunger went 5, 4, 3. Luna was never fed, so Luna's hunger is still 5. Luna played once, so Luna's happiness is 6, and Rocky's is still 5.

Each pet has its own copy of every attribute. rocky.feed() changes rocky.hunger and nothing else, the same way row.append changed row and not other in the opener.

The last line says Pet is now a class, like str and list. __main__ is the name Python gives the file you ran, so the line means the class Pet, from this file.

Round 2

a = Pet("Mochi")

for i in range(7):
    a.feed()
    a.play()

print(a.report())
Predict first. What is printed? Then: does the answer make sense for a pet?
verified output
Mochi: hunger -2, happiness 12

Each pass through the loop feeds Mochi once and plays once. Seven passes: hunger is 5 take away 7, which is -2, and happiness is 5 add 7, which is 12.

The program does what the code says, but the pet makes no sense. A hunger of -2 means nothing, and nothing in the class stops it. Section 5 shows how to fix that.

Round 3

print(b.report())
Predict first. How many pets does this code make? What two lines are printed?

Mochi: hunger 3, happiness 5

One pet. Only Pet(...) makes a pet, and it appears once. b = a does not copy Mochi. It gives the same pet a second name, so feeding b feeds a. To count the pets in a program, count the calls to Pet(...).

Section 4 · 15 minutes

Six broken pets

Each program has exactly one mistake. With a partner, for each one: predict what the terminal says, find the mistake, and fix it. Ninety seconds each. Broken pets 3, 4, and 5 use the working Pet class from section 2, so they only show the lines below it.

Broken pet 1

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 5

    def feed():
        self.hunger = self.hunger - 1


rocky = Pet("Rocky")
rocky.feed()
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
TypeError: Pet.feed() takes 0 positional arguments but 1 was given

The mistake. def feed(): has no self. rocky.feed() always sends rocky in as the first value, and this feed has no parameter to put it in. The error says so: 0 parameters, but 1 value was given.

The fix. def feed(self):

Broken pet 2

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 5

    def feed(self):
        hunger = hunger - 1


rocky = Pet("Rocky")
rocky.feed()
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
UnboundLocalError: cannot access local variable 'hunger' where it is not associated with a value

The mistake. hunger = hunger - 1 has no self. in front. Without it, hunger is an ordinary variable inside feed. It has never been given a value, so Python cannot read it to take 1 off. The pet's hunger is self.hunger.

The fix. self.hunger = self.hunger - 1

Broken pet 3

rocky = Pet("Rocky")
Pet.feed()
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
TypeError: Pet.feed() missing 1 required positional argument: 'self'

The mistake. Pet.feed() calls the method on the class, not on a pet, so there is no pet to put in self. The error names the empty parameter.

The fix. rocky.feed()

Broken pet 4

rocky = Pet
print(rocky.name)
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
AttributeError: type object 'Pet' has no attribute 'name'

The mistake. rocky = Pet has no brackets, so no pet is made. rocky becomes a second name for the class itself, which the error calls a type object. The class has no name. Each pet gets its own name in __init__, and no pet was made.

The fix. rocky = Pet("Rocky")

Broken pet 5

rocky = Pet("Rocky")
rocky.feed(rocky)
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
TypeError: Pet.feed() takes 1 positional argument but 2 were given

The mistake. rocky.feed(rocky) sends rocky twice: once through the dot, which fills self, and once in the brackets. feed has 1 parameter and was given 2 values.

The fix. rocky.feed()

Broken pet 6

class Pet:
    def _init_(self, name):
        self.name = name
        self.hunger = 5


rocky = Pet("Rocky")
Predict first. What does the last line of the error say? What is the mistake, and what is the fix?
last line of the error
TypeError: Pet() takes no arguments

The mistake. _init_ has one underscore on each side, so Python does not treat it as the setup method. The class has no __init__, so Pet("Rocky") has nowhere to send the name. Some fonts draw two underscores as one long line, so count them.

The fix. def __init__(self, name):, with two underscores on each side.

Section 5 · 20 minutes

Build your own creature

A dragon, a robot, a houseplant, a moody cat, a boss from a game. Pick something and write a class for it in a new file.

The brief

  • An __init__ that takes at least the creature's name as a parameter.
  • At least 3 attributes that are numbers: health, energy, fuel, water, whatever fits your creature.
  • At least 2 methods, and each one changes at least one attribute.
  • A report method that returns one line about the creature, printed by the caller.
  • At least 2 creatures with different names, treated differently, that end with different reports. That is your proof that each one keeps its own attributes.
  • Your own class, not Pet with the names changed.

Check before you call it done

  • The class name starts with a capital letter.
  • __init__ has two underscores on each side.
  • Every method is indented inside the class.
  • Every method has self as its first parameter.
  • Every attribute inside a method has self. in front of it.
  • Every call has the object before the dot and nothing in the brackets for self: drake.fly(), not drake.fly(drake) and not Dragon.fly().
  • You made as many creatures as your program has calls to the class.

Stuck for an idea?

A dragon with health, fire, and age. A robot with battery, heat, and version. A houseplant with water, light, and leaves. A wizard with mana, spells, and wisdom.

Keep a number in range

Round 2 gave Mochi a hunger of -2. One if gate in feed, like the gates in session 1, fixes it: only take 1 off when hunger is above 0.

Predict first. Before you open this, write the condition the gate should check. 
    def feed(self):
        """Make this pet 1 less hungry, but never below 0."""
        if self.hunger > 0:
            self.hunger = self.hunger - 1

Hunger stops at 0. Happiness still reaches 12, because play has no gate yet. Writing that one is yours.

What to watch for

Use the quick check at the end of section 3 as a hinge. Count hands for each letter before anyone opens the answer. A (3) means the student thinks all pets share one hunger. C (4) can mean the student shared the two feeds out between the two pets. D means the student thinks an attribute exists only after a method has changed it, so __init__ is not yet real to them. If more than a few pick A or D, run piece 6 again on the projector before broken pets.

Slow down on round 3. b = a gives the same pet a second name; it does not make a second pet. Have the room count the calls to Pet( before anyone opens the answer.

Broken pets 1 to 5 are the mistakes to expect while students write their own class in section 5: self missing from the parameter list, self. missing in the body, calling on the class instead of the pet, missing brackets, and sending the pet twice. Broken pet 6 is hard to see on a projector, where two underscores can look like one line. Point at them and count them out loud.

Say self the same way every time: it is the object before the dot. Broken pets 1, 3, and 5 all come down to that one sentence.
