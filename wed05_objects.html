Making your own objects

Strings, lists, and dictionaries are objects that someone else designed. Today you write a class, the code that describes a new kind of object, and make virtual pets from it. Each pet keeps its own hunger and its own happiness. Then a Tree class draws a whole forest in a pygame window.

Section 1 · 30 minutes

Build a pet, one piece at a time

Do this now. Make a new file called pets.py. Type each piece as you reach it and run the file after each one. Answer each question before you open its answer.

Piece 1: an empty class

class Pet:
    pass

class Pet: starts a class called Pet. A class is code that describes a new kind of object: what each one stores and what each one can do. Class names start with a capital letter, so you can tell a class from a variable. pass means nothing here yet. Python needs at least one line inside a class, and pass is a line that does nothing.

Predict first. You run this file. What appears in the terminal?

Nothing. The file describes what a pet is, but no line makes a pet, and no line prints. Writing a class does not make an object.

Piece 2: setting up a new pet

class Pet:
    def __init__(self, name):
        self.name = name


rocky = Pet("Rocky")
print(rocky.name)
Predict first. What does it print? Then say what the difference is between Pet and rocky.
verified output
Rocky

Pet is the class. rocky is one pet made from it. A thing made from a class is called an object or an instance of that class. The two words mean the same thing.

Pet("Rocky"), with brackets, makes a new pet. Python makes an empty object, then straight away runs __init__ on it, with self set to the new object and name set to "Rocky". __init__ is short for initialise, which means set up. It has two underscores on each side.

self.name = name stores the name on this pet. name is a parameter, and like every parameter it is gone when __init__ finishes. self.name belongs to the pet and stays. rocky.name reads it back: rocky's name.

Piece 3: numbers every pet starts with

class Pet:
    def __init__(self, name):
        self.name = name
        self.hunger = 5
        self.happiness = 5


rocky = Pet("Rocky")
print(rocky.name, rocky.hunger, rocky.happiness)
Predict first. Pet("Rocky") only passes a name. What does it print, and where do the other two numbers come from?
verified output
Rocky 5 5

Every new pet starts with hunger 5 and happiness 5, because __init__ sets them to 5 for every pet it sets up. A value stored on an object like this is called an attribute. A pet has three: name, hunger, and happiness. Only the name comes from the line that makes the pet. To let pets start with different hunger, you would add a hunger parameter to __init__ and pass a number in.

Piece 4: things a pet can do

A function written inside a class is called a method. Add these two below __init__, indented 4 spaces, the same as __init__, so they are inside the class.

    def feed(self):
        """Make this pet 1 less hungry."""
        self.hunger = self.hunger - 1

    def play(self):
        """Make this pet 1 happier."""
        self.happiness = self.happiness + 1
Predict first. self appears in two kinds of places in feed. Find both and say what each one does. Then: rocky.feed() has nothing in its brackets, but feed has one parameter. Where does the value of that parameter come from?

The first place is def feed(self):, the parameter list. The first parameter of every method is self. It holds the pet the method is working on.

The second place is self.hunger = self.hunger - 1, in the body. self.hunger means this pet's hunger. The line reads this pet's hunger, takes 1 off, and stores the answer back on the same pet.

The value comes from the dot. When you write rocky.feed(), Python runs feed with self set to rocky. The object before the dot becomes self. luna.feed() runs the same lines with self set to luna.

Piece 5: a method that returns

Session 2's rule holds inside a class too: a function that works out a value returns it, and the caller prints it. report builds one line about the pet and returns it. Add it below play.

    def report(self):
        """Return one line about this pet."""
        return f"{self.name}: hunger {self.hunger}, happiness {self.happiness}"

Then, below the class, make a pet and call report two ways:

rocky = Pet("Rocky")
rocky.report()
print(rocky.report())
Predict first. Two calls to report, one inside print and one not. What appears in the terminal?
verified output
Rocky: hunger 5, happiness 5

One line, not two. rocky.report() on a line by itself returns the line and nothing prints it, so it is thrown away. print(rocky.report()) prints whatever report returned. This is session 2's print is not return, inside a class.

Piece 6: two pets at once

Here is the whole of pets.py. The part at the bottom makes two pets and treats them differently.

pets.py

"""Session 5: a class for a virtual pet, and two pets made from it."""


class Pet:
    """A virtual pet that keeps its own name, hunger, and happiness."""

    def __init__(self, name):
        self.name = name
        self.hunger = 5
        self.happiness = 5

    def feed(self):
        """Make this pet 1 less hungry."""
        self.hunger = self.hunger - 1

    def play(self):
        """Make this pet 1 happier."""
        self.happiness = self.happiness + 1

    def report(self):
        """Return one line about this pet."""
        return f"{self.name}: hunger {self.hunger}, happiness {self.happiness}"


# make two pets from the one class
rocky = Pet("Rocky")
luna = Pet("Luna")

rocky.feed()
rocky.feed()
luna.play()

print(rocky.report())
print(luna.report())
Download pets.py
Predict first. Write both lines on paper before you open the answer. Then say why Luna's hunger is not 3.
verified output
Rocky: hunger 3, happiness 5
Luna: hunger 5, happiness 6

Rocky was fed twice, so Rocky's hunger went 5, 4, 3. Luna was never fed, so Luna's hunger is still 5. Luna played once, so Luna's happiness is 6, and Rocky's is still 5.

Each pet has its own copy of every attribute. rocky.feed() changes rocky.hunger and nothing else.

A forest of trees

A pet keeps numbers and reports them in the terminal. A tree can keep numbers too, and draw itself in a pygame window from those numbers. The program in this section makes seven trees from one Tree class, keeps them in one list, and draws every tree in the list.

Download forest.py

Tree piece 1: setting up a new tree

class Tree:
    """A tree that keeps its own place, height, and leaves, and draws itself."""

    def __init__(self, x, height):
        self.x = x
        self.height = height
        self.leaf_size = 0

x is how many pixels from the left edge of the window the tree stands. height is how tall its trunk is, in pixels.

Predict first. Tree(80, 40) makes one tree. What are its three attributes, and what value does each one hold?

x is 80 and height is 40. The two values in the brackets go into the parameters in order: 80 into x, 40 into height. __init__ stores each one on the tree with self. in front.

leaf_size is 0. No value in the brackets sets it. __init__ sets it to 0 for every new tree, the way it set hunger to 5 for every new pet.

Piece 3 in section 1 said that to let pets start with different hunger, you would add a parameter to __init__. Tree does that with height, so each tree can start at its own height.

Tree piece 2: things a tree can do

    def grow(self, amount):
        """Make this tree amount pixels taller."""
        self.height = self.height + amount

    def add_leaves(self):
        """Give this tree a round clump of leaves."""
        self.leaf_size = 30
Predict first. grow has two parameters, self and amount. The call tree.grow(20) has one value in its brackets. Where does the value of each parameter come from?

The first parameter, self, gets its value from the dot. The tree before the dot becomes self, the same as in rocky.feed().

The second parameter, amount, gets its value from the brackets: 20. So tree.grow(20) adds 20 to that tree's height and to no other tree's.

add_leaves has only self, so it is called with empty brackets: tree.add_leaves(). It sets leaf_size to 30.

Tree piece 3: a tree draws itself

    def draw(self, screen):
        """Draw this tree's trunk, then its leaves if it has any."""
        top = GROUND - self.height
        pygame.draw.rect(screen, BARK, (self.x - 5, top, 10, self.height))

        if self.leaf_size > 0:
            pygame.draw.circle(screen, LEAVES, (self.x, top), self.leaf_size)

draw puts the tree in the window. Its parameter screen is the window to draw on. GROUND, BARK, and LEAVES are set at the top of forest.py: BARK and LEAVES are the two colours, and GROUND is 340, the y where the grass starts. In a pygame window y counts down from the top, as in session 3's cipher console, so y = 340 is 340 pixels below the top edge. The window is 640 wide and 400 tall.

pygame.draw.rect is the one from session 3: the window, a colour, then the rectangle's left edge, top edge, width, and height. pygame.draw.circle is new. It takes the window, a colour, the centre of the circle as an (x, y) pair, and the radius: the distance from the centre to the edge, in pixels.

Predict first. A tree has height 100. What is top for that tree? Then: why does the code take the height away from GROUND instead of adding it?

The first part: top is 340 take away 100, which is 240.

The second part: y counts down from the top of the window, so a point higher up has a smaller y. The trunk goes up from the grass, so its top edge needs a y smaller than 340. Adding would give 440, which is below the bottom of the 400 pixel window.

The rectangle starts at top and is self.height pixels tall, so its bottom edge is at 340, on the grass. Its left edge is at self.x - 5 and it is 10 wide, so the trunk is centred on x.

The circle's centre is the top of the trunk, so the leaves sit on the trunk. It is drawn after the trunk, so it covers the top of the trunk. The if gate means a tree with leaf_size 0 gets no circle.

Tree piece 4: a forest in a window

This is the bottom of forest.py. forest starts as an empty list. The for loop makes seven trees and adds each one to the list with append. The window loop is the one from session 4, with two keys: G and L. Each key runs a for loop over the list, so one key press changes every tree.

# make seven trees, 80 pixels apart, each one 20 taller than the one before
forest = []
for i in range(7):
    forest.append(Tree(80 + i * 80, 40 + i * 20))

screen = pygame.display.set_mode((WIDTH, HEIGHT))
clock = pygame.time.Clock()

running = 1
while running:
    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = 0
        if event.type == pygame.KEYDOWN and event.key == pygame.K_g:
            for tree in forest:
                tree.grow(20)
        if event.type == pygame.KEYDOWN and event.key == pygame.K_l:
            for tree in forest:
                tree.add_leaves()

    screen.fill(SKY)
    pygame.draw.rect(screen, GRASS, (0, GROUND, WIDTH, HEIGHT - GROUND))
    for tree in forest:
        tree.draw(screen)

    pygame.display.flip()
    clock.tick(60)

pygame.quit()
Predict first. Work out two things before you run it. First: what are the seven starting heights, from left to right? Second: you press G three times, then L. How tall is the tallest tree then, and what y is the top of its trunk? Now run forest.py, look, then press G three times and L.

Section 5 · 15 minutes

Build your own

Pick one: a creature of your own, or a forest of your own. Each has its own brief below.

A creature

A dragon, a robot, a houseplant, a moody cat, a boss from a game. Pick something and write a class for it in a new file.

The creature brief

  • An __init__ that takes at least the creature's name as a parameter.
  • At least 3 attributes that are numbers: health, energy, fuel, water, whatever fits your creature.
  • At least 2 methods, and each one changes at least one attribute.
  • A report method that returns one line about the creature, printed by the caller.
  • At least 2 creatures with different names, treated differently, that end with different reports. That is your proof that each one keeps its own attributes.
  • Your own class, not Pet with the names changed.

A forest

Save a copy of forest.py under a new name and change the Tree class. The window loop can stay as it is.

The forest brief

  • At least one new attribute that each tree keeps for itself, set in __init__: its own leaf colour, its own trunk width, a number of fruit.
  • At least one new method, with at least one parameter after self, the way grow has amount. It changes at least one attribute.
  • draw uses your new attribute, so you can see it in the window.
  • At least 5 trees in the list, made with a for loop.
  • At least one key that changes every tree, with a for loop over the list.

Check before you call it done

  • The class name starts with a capital letter.
  • __init__ has two underscores on each side.
  • Every method is indented inside the class.
  • Every method has self as its first parameter.
  • Every attribute inside a method has self. in front of it.
  • Every call has the object before the dot and nothing in the brackets for self: drake.fly(), not drake.fly(drake) and not Dragon.fly().
  • You made as many creatures as your program has calls to the class.
  • In a forest, every pygame.draw line for a tree is inside draw, and the window loop calls draw on every tree in the list.
